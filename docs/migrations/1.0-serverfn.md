# Migrating to 1.0 — server functions (rfc-server-v5)

One consolidation across `@sigx/server` and `@sigx/vite` (rfc-server-v5,
signalxjs/core#692): the direct authoring form is gone, the handler takes one
object, the stable key is the only route, the wrapper carries one descriptor,
and the endpoint takes the registry directly. This document owns the
migration for core; `@sigx/actors` and the lynx loader link here from their
own changelogs rather than duplicating it.

## The model, in five lines

- **One form.** `serverFn({ input?, handler, … })` and
  `serverStream({ input?, handler, … })`. Every function takes one input or
  none; more than one wire argument is a 400 everywhere.
- **One handler shape.** `handler({ input, rq })` — destructure what you
  need. Policies, middleware, `perRequest` and `invalidates` are unchanged.
- **One route.** `POST|GET {base}/<id>/<name>`. The content hash is a version
  tag the stub sends; a mismatch is `409` with `code: 'version-skew'`, and
  `404` means only "unknown function".
- **One descriptor.** `fn.__sigx` holds everything the endpoint reads;
  `fn.__sigxKey` stays the build-stamped key.
- **The registry is an option.** `functions: serverFns` on every endpoint
  entry; `resolve` remains as the escape hatch (no skew detection there).

## The function that cannot be mechanically converted

The common pre-v5 direct-form shape took several arguments and checked
everything it used in the body:

```ts
// BEFORE — direct form, two arguments, compile-time types only
export const addToCart = serverFn(async (rq, productId: string, qty: number) => {
    const user = await requirePrincipal<User>(rq);
    return db.cart.add(user.id, productId, qty);
});
// call site
await addToCart(sku, 2);
```

Three cuts:

1. **The arguments become one input, with a schema.** The types were never
   enforced on the wire; now they are:

   ```ts
   const AddToCart = z.object({ productId: z.string(), qty: z.number().int().positive() });
   ```

2. **The handler destructures.** `rq` is still the same context object;
   `input` is the validated value:

   ```ts
   export const addToCart = serverFn({
       input: AddToCart,
       handler: async ({ input: { productId, qty }, rq }) => {
           const user = await requirePrincipal<User>(rq);
           return db.cart.add(user.id, productId, qty);
       }
   });
   ```

3. **Call sites pass the object.** `await addToCart({ productId: sku, qty: 2 })`.
   `useData(() => [getCart, { userId }])` and `useAction(addToCart)` are
   unchanged in shape — the tuple is `[fn]` or `[fn, input]`.

A function with no input keeps its zero-argument callable:
`serverFn({ handler: async ({ rq }) => … })` is called as `vote()`.

## Verifying the migration

- `pnpm typecheck` — every removed member and the old handler arity are type
  errors; nothing is left to find at runtime.
- The build errors on any `*.server.ts` in row 20's list, naming the file
  and line.
- A stale tab after a deploy now logs `version skew … reload` on a 409
  instead of a 404 — if your client code branches on 404 for skew, it needs
  row 14.
- `grep -rnE "__sigx(Fn|Name|Stream|Get|CacheControl|Form|Anon|Invalidates)\b" src/ test/`
  — every read of a folded stamp. `__sigxKey` is not in the list: it stays.
