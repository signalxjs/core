# Migrating to 0.15 — the guard split (rfc-server-v4)

One conceptual change across two repos: `@sigx/server`'s single guard
primitive (`use:` / `unguarded` / `serverFnPreset` / the endpoint `guard`
option) split into **middleware**, **authentication**, and **authorization**
(rfc-server-v4, signalxjs/core#607), and the runtime became **fail-closed** —
a server function that declares nothing now denies anonymous callers on
every transport. This document owns the migration for `@sigx/server` +
`@sigx/vite` (core 0.15.0) and, when its release lands, `@sigx/actors`
(signalxjs/actors#17); the actors changelog links here rather than
duplicating.

## The model, in five lines

- **Middleware** does work — global, ordered, every transport, never
  per-function-disableable: `createServerApp({ middleware: [...] })`.
- **Authentication** resolves *who is calling*, once per request store:
  `createServerApp({ authenticate: (rq) => principal | null })`.
- **Authorization** decides *may this caller do this* — per definition
  (`authorize:`), else the app default, else `requireAuthenticated`. It runs
  AFTER `input` validation, so a policy sees the validated input as the
  resource.
- **`allowAnonymous: true`** waives only the identity gate. Middleware and
  authentication still run.
- **A miss denies.** No app configured ⇒ anonymous ⇒ everything not
  `allowAnonymous` is a 401.

## The table

| # | You had | You write now | Mechanical? |
|---|---|---|---|
| 1 | `serverFn({ handler })` with no declarations | Either configure the app (`createServerApp({ authenticate })` + `sigxServer({ serverApp })`) or declare `authorize:` / `allowAnonymous: true`. **A bare fn now denies 401** where it ran open. | manual choice, then mechanical |
| 2 | `unguarded: true` | `allowAnonymous: true` | yes — but note middleware and authentication now run for these fns: a throwing authenticator now 500s a formerly-unguarded endpoint, and rate-limit middleware now applies (both are the point) |
| 3 | `use: [guard]` where the guard *decides* (throws 401/403) | `authorize: (principal, rq, op) => boolean` — strict-`true`-to-allow, run post-validation (`op.input` is the validated resource), receives the principal instead of digging cookies out of `rq` | classify, then mechanical |
| 4 | `use: [guard]` where the guard *does work* (logging, rate limiting, propagation) | app `middleware` (`createServerApp({ middleware })`) — wire-only behavior is `if (fn.transport !== 'wire') return;` in the body | classify, then mechanical |
| 5 | `serverFnPreset({ use })` / `preset.stream` | Removed. App-wide policy → the app default (`createServerApp({ authorize })`); a module-scope policy → one imported identifier per fn (`authorize: adminOnly`) | mechanical for the single-auth-guard preset |
| 6 | endpoint `guard` option (`handleServerFnRequest` / `createServerFnHandler`) and the vite `guard` specifier | app `middleware` (same pre-decode slot, plus in-process coverage); dev wiring is `sigxServer({ serverApp: '/src/server-app.ts' })` | yes |
| 7 | `sigxServer({ requireGuards })` | `requireAuthorization` — passes on `authorize:` / literal `allowAnonymous: true` / configured `serverApp` | yes |
| 8 | `info.symbol === ''` (the in-process discriminator) | `info.transport === 'in-process'` (`'wire'` for the four HTTP transports); `symbol` is pure identity again | yes |
| 9 | `ServerFnGuard` type references | `ServerMiddleware` (work) or `ServerPolicy` (decisions), per the row-3/4 classification | classify, then mechanical |
| 10 | Tests calling guarded fns via `fn.with({ context })` with pre-seeded `rq.locals` | Inject the identity: `createTestServerFnContext(init, { principal })`, or stamp an app with `stubServerApp({ authenticate })` (returns the restore) | manual |
| 11 | `stampServerFnKey` expectations of `__sigxGuardChecked` | Gone — the stamp machinery retired with the fail-closed runtime | yes |

`@sigx/actors` (when its 0.15-pinned release lands): `use`/`methodUse`/
`unguarded` on actors, workers and jobs → `authorize`/`methodAuthorize`/
`allowAnonymous` (policies receive `op.resource = { kind, type, key,
method }` — per-instance authorization at last); `stampCallBag` identity
propagation → automatic (`ctx.principal`, carried in a first-class envelope
slot; the bag stays for app data); `sigxActors({ requireGuards })` →
`requireAuthorization`.

## The guard that cannot be mechanically split

The common pre-v4 shape did all three jobs in one function — verified a
cookie, threw 401, and stashed the result:

```ts
// BEFORE — one guard, three jobs
export function requireUser(rq: ServerFnContext): void {
    const user = verifySessionCookie(rq.request);   // authentication
    if (!user) throw new ServerFnError(401, 'sign in');  // authorization
    rq.locals.user = user;                          // propagation
}
// …repeated in `use: [requireUser]` on every function.
```

Three cuts:

1. **The verify becomes the authenticator.** Its body is already right —
   return the principal or `null`, never throw for a bad cookie:

   ```ts
   // src/server-app.ts
   export const app = createServerApp({
       authenticate: (rq) => verifySessionCookie(rq.request)
   });
   ```

2. **The 401 becomes the default policy** — which is the built-in
   `requireAuthenticated`, i.e. nothing to write. The sign-in target itself
   (the one function that must accept anonymous callers) declares
   `allowAnonymous: true`.

3. **The propagation is deleted.** `rq.locals.user` reads become
   `await principal(rq)` (or `requirePrincipal(rq)` for the non-null type
   with no cast). The pipeline memoizes it once per request store — one SSR
   render with five cells decodes the session once.

## Verifying the migration

- `grep -rn allowAnonymous --include='*.server.ts' src/` — the app's whole
  anonymous-reachable surface, the list a security review reads.
- The build gate (`requireAuthorization`, default on) errors on any function
  whose access is undecided, naming its file and line.
- A protected function invoked in a test with no injected identity rejects
  `401 'Authentication required'` — if a test suddenly does this, it needs
  row 10.
